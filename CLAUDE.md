# Website Modul3D — project instructions

Проект для генерации сайтов через Claude: пользователь описывает нужный сайт словами, Claude
проектирует, собирает и (там, где возможно) тестирует результат автоматически.

## Дизайн-принципы (что Claude должен соблюдать в каждом сайте)

- Современная сеточная вёрстка (grid/flexbox), понятная визуальная иерархия.
- Осознанная типографика: ограниченная пара шрифтов, чёткая шкала размеров (h1–h6, body, caption).
- Единая система отступов (например, шкала 4/8px) — никаких случайных значений margin/padding.
- Уместная, ненавязчивая анимация и микро-интеракции (hover, transitions), а не эффекты ради эффектов.
- Свет/тёмная тема должны быть предусмотрены с самого начала, а не добавляться потом.
- Дизайн должен ориентироваться на реальные современные сайты и актуальные тренды в индустрии
  заказчика — избегать шаблонного "generic AI-дизайна" (дефолтные градиенты, клипарт-иконки,
  безликие лендинги). Перед версткой стоит явно спросить/зафиксировать референсы (индустрия,
  похожие сайты, тон бренда), если пользователь их не дал.
- Адаптивность (mobile/tablet/desktop) обязательна для любого лендинга или сайта.
- Доступность (контраст, alt-тексты, семантическая разметка) — не опция, а часть готового результата.

## Рабочий процесс

1. Уточнить у пользователя: назначение сайта, аудиторию, референсы/конкурентов, бренд-цвета
   (если есть), обязательные разделы/страницы.
2. Спроектировать структуру (разделы, навигация, ключевые CTA) прежде чем писать код/вёрстку.
3. Собрать сайт (HTML/CSS/JS или выбранный стек — уточнить у пользователя, если не задан).
4. Проверить результат:
   - визуально (скриншоты в разных размерах экрана);
   - по ссылкам/формам, если есть интерактивность;
   - на консольные ошибки.
5. Показать результат пользователю и внести правки по фидбеку.

## Установленные skill-паки (agent skills)

Установлены в `.agents/skills/` (симлинкнуты под Claude Code в `.claude/skills/`) через
`npx skills@latest add ...`. Claude должен опираться на них при дизайне и вёрстке:

- **emilkowalski/skills** ("Elkovals" из ролика — это Emil Kowalski, ex-Vercel, автор Sonner/Vaul):
  `emil-design-eng`, `apple-design`, `animation-vocabulary`, `review-animations`,
  `improve-animations`, `find-animation-opportunities`, `pick-ui-library`, `prototype`,
  `animate`, `animate-expo`, `ask-sonner`, `write-swift`. Про современные лейауты, типографику,
  осмысленную анимацию, выбор UI-библиотек.
- **Leonxlnx/taste-skill** ("TAST" из ролика — это "taste", вкус): `design-taste-frontend` (+ v1),
  `gpt-taste`, `high-end-visual-design`, `minimalist-ui`, `industrial-brutalist-ui`, `brandkit`,
  `stitch-design-taste`, `image-to-code`, `imagegen-frontend-web`, `imagegen-frontend-mobile`,
  `redesign-existing-projects`, `full-output-enforcement`. Про то, чтобы брать вдохновение из
  реально сильных сайтов вместо шаблонного AI-дизайна.

**Не установлено:** `pbakaus/impeccable` ("Impeccable Design" из ролика) — попытки поставить его
(`npx impeccable install` и прямой `git clone` официального репозитория) заблокировал классификатор
безопасности этой сессии. Скорее всего потому, что `impeccable` — общее имя пакета в npm, и
запуск произвольного пакета под таким именем без верификации, что это именно код pbakaus,
небезопасен (риск namesquatting). Если он тебе нужен — либо ставь вручную сам на своей машине,
либо явно подтверди, что понимаешь риски и хочешь, чтобы я повторил попытку.

## Прочий инструментарий

- **Дизайн-референсы / handoff**: коннектор Figma MCP ("FigM MCP" из ролика) — ПОДКЛЮЧЁН.
  Доступны инструменты `mcp__Figma__*`: `get_design_context`, `get_screenshot`, `get_metadata`,
  `get_variable_defs`, `generate_diagram`, запись дизайна обратно в Figma (`use_figma`,
  `create_new_file`) и Code Connect. Перед вызовом `use_figma` обязательно читать скилл
  `/figma-use`.
- **Автоматическое тестирование ("Playri" из ролика = Playwright)**: НАСТРОЕНО как часть проекта
  (не как коннектор claude.ai — Playwright не хостится через OAuth, это локальный
  браузер-движок). Установлено: `@playwright/test` в `devDependencies`, конфиг
  `playwright.config.js` (использует предустановленный Chromium в `/opt/pw-browsers/chromium`,
  скачивание браузера не требуется), тесты в `tests/` (пример: `tests/homepage.spec.js`).
  Запуск: `npm test` (= `playwright test`), отчёт — `npm run test:ui`.
  Важно: из этой облачной песочницы нет доступа к произвольным внешним сайтам — тестировать
  можно локальные файлы/dev-сервер проекта (см. `testUrl` в примере теста), это и есть
  реальный сценарий использования (тестируем то, что сами собрали).
  Дополнительно, прямо в этой сессии есть браузерная автоматизация (Claude in Chrome) для
  визуальных проверок и скриншотов без написания кода теста.
- **Публикация/предпросмотр**: готовые статические страницы можно публиковать как Artifact для
  быстрого предпросмотра и итерации с пользователем.
